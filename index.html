The problem

NixOS can't run most software built for normal Linux.

Vendor tools, pip wheels, npm packages with native binaries, and AppImages all expect their loader at /lib64 and their libraries in /usr/lib. NixOS keeps every package in its own hash-named directory in /nix/store instead, so those paths don't exist and the program stops before its first line runs.

It's a deliberate trade-off, and it's what makes NixOS reproducible. But whole distributions like Omarchy can't run on it today.

stock NixOS
$ ./some-vendor-tool
Could not start dynamically linked executable: ./some-vendor-tool
NixOS cannot run dynamically linked executables intended for generic
linux environments out of the box.

$ ls /usr/lib /lib
ls: cannot access '/usr/lib': No such file or directory
ls: cannot access '/lib': No such file or directory
1 of 4 Why Omnix

Prebuilt software just runs.

Omnix adds the standard Linux layout on top of NixOS: a loader at /lib64, a declared set of common libraries in /usr/lib, a fresh ld.so.cache, and a /bin that resolves #!/bin/bash. Manylinux wheels, rustup, vendor SDKs, Electron apps, and Playwright browsers start without patching or wrappers.

omnix
$ ./some-vendor-tool --version
some-vendor-tool 4.2.0

$ readlink /lib64/ld-linux-x86-64.so.2
/nix/store/…-nix-ld/libexec/nix-ld

$ python3 -c 'import ctypes.util as u; print(u.find_library("z"))'
libz.so.1

$ head -1 ./install.sh && ./install.sh
#!/bin/bash
installed.
2 of 4 Why Omnix

Nothing compiles. Everything downloads.

The rule is add, never relocate. Omnix never patches or moves a nixpkgs package, so every store path still matches the official binary cache at cache.nixos.org. Installs and upgrades are downloads, not builds.

It needs no infrastructure of its own either: the installer ISO lives on GitHub Releases, and everything else comes straight from the NixOS cache.

3 of 4 Why Omnix

Pick your desktop at install time.

The base stays small. Everything opinionated lives in a flavor, a complete system in its own repository. Autarchy ports Omarchy's keyboard-driven Hyprland desktop. Atrium is a polished, mouse-first KDE Plasma desktop with independent virtual desktops on every monitor.

The installer reads the flavor list live, so new styles show up without a new ISO.

4 of 4 Why Omnix

Every change rolls back.

Your system is a flake that you own in /etc/nixos, and your flavor is one input in it. Switch from Atrium to Autarchy by changing that input and rebuilding.

The FHS layer is generated from your configuration and versioned with it, so rolling back a generation rolls back the library layout too. The previous system is always one entry away in the boot menu.

Install

Five choices and one download.

The installer is a text menu. Nothing touches your disk until you confirm.

  1. Step 1

    Boot the ISO

    Write it to a USB stick and run sudo omnix-install. Wired networks connect on their own; Wi-Fi opens nmtui.

  2. Step 2

    Pick a filesystem

    Choose the disk, then a filesystem.

    ext4btrfsxfs
  3. Step 3

    Encrypt?

    Turn on LUKS full-disk encryption. Recommended for laptops.

    yesno
  4. Step 4

    Choose a flavor

    Then set your user, password, hostname, and timezone.

    AutarchyAtriumMinimal
  5. Step 5

    Sync from the cache

    Everything downloads prebuilt from cache.nixos.org. NVIDIA GPUs get their driver. Reboot.
