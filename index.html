Why Omnix

A next-generation NixOS that runs everything.

Not a fork, not a reimplementation: NixOS itself, with the standard Linux filesystem layout laid back on top. Nothing is patched and nothing is overlaid, so every package stays exactly as its maintainers shipped it.

That one missing layer is what everything else follows from. Your existing Linux software runs unmodified. Any desktop you want runs on it. And the whole system is one text file you can read, change, and roll back.

Choose your desktop

Pick a desktop. Switch any time.

Every Omnix desktop shares the same NixOS base. Choose Hyprland - Omarchy for keyboard-driven tiling, or KDE Plasma - Atrium for a familiar taskbar desktop.

Don’t like the look? Pick another theme and switch immediately. Hyprland - Omarchy includes Omarchy’s built-in themes, from Tokyo Night and Catppuccin to Gruvbox, Nord and Rosé Pine. Press Super + Ctrl + Shift + Space, choose one, and the bar, window borders, terminal and editor change color on the spot, with no rebuild and no logout. Try it in the preview.

Want a different desktop altogether? Change one line in your configuration and rebuild. Your previous desktop stays in the boot menu, so trying something new is never a one-way trip.

Hyprland tiles every window automatically. Open and close windows, switch workspaces and try Omarchy’s themes.

KDE Plasma - Atrium

Omarchy ideas, on KDE Plasma.

KDE Plasma - Atrium is a polished, mouse-first KDE Plasma 6 desktop for people who like windows, a taskbar and a mouse. It borrows keyboard habits Omarchy users will recognize, while staying a familiar desktop.

The whole desktop is declared in Nix through home-manager and plasma-manager, so a fresh install looks exactly like the screenshot and you can edit it as text. Bringing more of Omarchy’s ideas to KDE Plasma is where this flavor is headed.

Rollback

Every update can be undone.

Each Omnix system update becomes a new entry in the boot menu. If one breaks something, pick the previous entry: system apps, libraries and settings come back as they were. Your files and personal settings stay untouched.

Your system is a Nix flake that you own in /etc/nixos, and your desktop is one input in it. The Linux compatibility layer is versioned with it, so a rollback restores the library layout too.

Compatibility

The Linux apps you already use, working on NixOS.

Python wheels, rustup, AppImages, Electron apps and vendor SDKs expect standard Linux folders such as /bin/bash, /usr/lib and /lib64. Omnix adds them to NixOS.

Add, never relocate. Packages stay unmodified in /nix/store and download from the same cache.nixos.org as NixOS. Omnix uses no overlays or patches, so it asks nothing special of nixpkgs maintainers.

Nix packages. Linux compatibility.
nixpkgs                 // unmodified packages
  |-- cache.nixos.org    // download when available
  '-- local builds      // compile when needed
             |
             v
/nix/store              // packages stay here
             |
             v
Omnix FHS layer         // familiar Linux paths
  |-- /bin/bash         // shell for scripts
  |-- /usr/lib          // shared libraries
  '-- /lib64            // compatibility loader
Your system, in text

Save your entire computer configuration as a git repo, and share it.

Your whole system is one file you own in /etc/nixos: the packages, the desktop, the keyboard shortcuts, the wallpaper. Change it in a text editor, commit it, and the history is the record of what you changed and when.

Share it as an Omnix flake. Point a friend, a teammate or an AI assistant at the repo and they get the same machine. Nothing is hidden in a GUI, and nothing is lost when the disk dies.

~/.config/omnix
$ git init && git remote add origin
  git@github.com:you/omnix-config.git

$ cat flake.nix
{
  // the whole machine, as text
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  inputs.omnix.url = "github:Omnix-Linux/Omnix";
  outputs = { nixpkgs, omnix, ... }: {
    nixosConfigurations."laptop" = nixpkgs.lib.nixosSystem {
      modules = [
        omnix.nixosModules.default
        ./hardware.nix      // disks, GPU
        ./desktop.nix      // Hyprland - Omarchy
      ];
    };
  };
}

$ git push
✓ same machine, anywhere
Rust, optimized

A luxury experience for building Rust apps.

On Omnix, cargo is aliased to soldr cargo. You type the commands you already know; underneath, the build is cleaned up for you — the right toolchain fetched and pinned, each compilation cached, and nothing rebuilt that does not have to be.

Warm builds come back in seconds. The cache is content-addressed, so a build reuses the exact compilation it already did — and shares it across branches and pull requests, which a per-branch CI cache cannot do. Cross-PR builds run about twice as fast.

Cross-compilation is a first-class citizen. The tools for it are built in, not bolted on, so cross-compiling is as easy as compiling: one command provisions the SDK and builds a macOS binary from Linux, or a Windows one, without renting a runner to produce it.

cargo · aliased on Omnix
# cargo is aliased to soldr cargo

$ cargo build --release
  // warm cache · no recompile

$ cargo build --target mac-arm64
  // macOS, built from Linux
  ✓ your-app (macOS arm64)

$ cargo test
  // shares the cache across branches

The alias points at Soldr, the toolchain behind it — developed by the same person behind Omnix and used to build its own projects. It is beta software: pin the release you use.

Coming next

Portable programs and a WebAssembly runtime.

Running prebuilt software already works out of the box: the base ships a loader, so ordinary Linux programs run unmodified. What comes next covers the two kinds that do not need a Linux binary at all.

Actually Portable Executables (APE) One file that runs on many operating systems

Cosmopolitan-style single-file programs, treated as a first-class app beside Nix packages: download one file and it runs, whichever system you land on. No build step, no per-platform binaries to chase.

app.ape            // one file, many OSes
  '-- first-class app  // runs like any app
A WebAssembly runtime for micro apps Small, sandboxed, no Linux build needed

Small sandboxed WASM modules, aiming for near-native speed on top of a stable kernel API — programs with no Linux build at all, hosted on an interface that stays stable as the system underneath it changes.

micro.wasm          // no Linux build needed
  '-- kernel-API      // sandboxed, stable host

Planned, not shipped. Both of these are on the roadmap; the loader and the desktop work above are what Omnix does today.

FAQ

Questions, answered.

What is Omnix?

Omnix is NixOS with the standard Linux filesystem layout. It adds that layout as a layer — no forked packages, no overlays — so Omarchy's Hyprland desktop, KDE Plasma - Atrium and prebuilt Linux software run unmodified, with declarative configuration and boot-menu rollbacks.

Can I run Omarchy on NixOS?

Yes. The Hyprland - Omarchy flavor of Omnix runs Omarchy's own Hyprland configuration, keybindings, themes and scripts on a NixOS base. Choose stable for a pinned Omarchy release (4.0.4) or latest to follow Omarchy's development branch.

Is there an Omarchy-like setup for KDE Plasma?

Yes. KDE Plasma - Atrium is a declarative KDE Plasma 6 desktop that borrows Omarchy habits such as a Meta+W overview, per-screen virtual desktops, the JetBrainsMono Nerd Font and fast key repeat, while staying a familiar, mouse-first taskbar desktop.

Can I change the look without reinstalling?

Yes. In Hyprland - Omarchy, press Super + Ctrl + Shift + Space and pick one of Omarchy's built-in themes; the bar, window borders, terminal and editor change immediately, with no rebuild. To change the whole desktop, change one line in your configuration and rebuild, and the previous desktop stays in the boot menu.

Is Omnix a NixOS fork?

No. Omnix is NixOS (nixos-unstable) with unmodified nixpkgs packages from cache.nixos.org. It adds the standard Linux filesystem layout as a layer built from nix-ld and envfs — symlinks and a library cache, with no overlays, no patched packages and nothing forked.

What does an Omnix rollback restore?

System apps, libraries, system settings and the Linux compatibility layer. Every update is a new boot-menu entry, so you can pick the previous one or run sudo nixos-rebuild switch --rollback. Files and personal settings in your home folder are not changed.

Will prebuilt Linux software run on Omnix?

Most prebuilt software that expects /bin/bash, /usr/lib and /lib64/ld-linux-x86-64.so.2 runs unmodified, including manylinux Python wheels, rustup, AppImages, Electron apps and Playwright's Chromium.

How is Omnix different from omarchy-nix?

omarchy-nix recreates Omarchy as a NixOS and home-manager configuration. Omnix runs Omarchy's own sources on a NixOS base with standard Linux paths, and also offers a KDE Plasma desktop. Both are independent community projects.

What hardware does Omnix support?

Omnix currently supports 64-bit Intel and AMD PCs (x86-64). The Try Omnix Docker app, which runs the real installer in a virtual machine, needs x86-64 Linux, Docker and KVM.

Is Omnix affiliated with Omarchy or NixOS?

No. Omnix is an independent project and is not affiliated with or endorsed by Omarchy, 37signals, Basecamp or the NixOS Foundation.
